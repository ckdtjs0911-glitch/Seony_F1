# F1 주말 보고서 자동화

대상: **Practice 1 / Practice 2 / Practice 3 / Qualifying / Race**.
각 세션에서 전체 선수의 결과, 랩 기록, 타이어 스틴트, 피트 진입을 수집합니다.
스프린트 퀄리파잉·스프린트 레이스도 포함하며, 열리지 않은 세션은 '일정 없음 / API 목록에 없음'으로 표시합니다.

## GitHub Actions

2026년 11월 28일부터 주말 자동화를 재개합니다. 주간 과거자료 보충 예약은 재개하지 않습니다.
보고서는 실제 열린 FP1·FP2·FP3·퀄리파잉·레이스·스프린트 퀄리파잉·스프린트 레이스
각 세션 종료 **3시간 후**부터 생성합니다. 예약 확인 시점에 따라 실행이 지연될 수 있습니다.
자동 적용은 한국 시간 **금요일 00:00~월요일 23:59**에만 합니다. GitHub에 등록한 cron은 UTC 기준
`7,22,37,52 15-23 * * 4`, `7,22,37,52 * * * 5,6,0`, `7,22,37,52 0-14 * * 1` 세 개입니다(`.github/report-pause.json`).
재개는 로컬 PC가 담당하지 않습니다. GitHub 실행기가 `resume_at`을 먼저 확인하며, 11월 28일 00:00 KST 전에는
자동 수집을 하지 않습니다. 재개 설정이 없거나 잘못돼도 수집하지 않습니다. 수동 요청은 이 자동 중지와 별개입니다.
예약 확인(`tools/session_report_schedule.py`)은 저장된 `catalog/sessions.json`과 `weekend-*/sessions.json`,
시도 기록만 읽고 외부 API를 호출하지 않습니다. 종료 3~4시간 사이이고 아직 자동 시도하지 않은 세션만
`sessions` 목록으로 넘기며, 수집 단계는 그 세션만 조회하고 다른 세션은 기존 스냅샷을 유지합니다.
명시적인 실제 종료 시각(`actual_date_end`)이 있으면 예정 종료보다 우선합니다. 조회한 일정에서 실제 종료가
더 늦으면 아직 3시간이 지나지 않은 자료를 수집하지 않고 그 종료 시각을 기록해 기다립니다.
세션별 첫 자동 시도는 `reports/catalog/report-attempts.json`에 기록합니다. 인증 설정 후 복구는 인증 대기 세션별로 한 번만 실행합니다.
변경 없음이나 새로 확보한 자료가 없는 경우에는 시도 기록만 커밋합니다.
선택된 세션 중 일부만 실패하거나 이후 단계가 실패해 보고서가 커밋되지 않으면, 수집에 성공한 세션도
`not_published`(완료 아님)로 기록하고 자동으로 다시 조회하지 않습니다. 재수집은 수동 실행으로 합니다.
완료 세션의 2시간·24시간 후 재갱신 같은 자동 정정은 하지 않습니다.
세션이 없는 날에는 갱신하지 않습니다. 동일한 데이터는 조회 시각이 바뀌어도
HTML을 재생성하지 않고, 누적 HTML 갱신·업로드·커밋·검토도 건너뜁니다.
수동 실행은 사용자의 명시적인 요청에 사용합니다.

## 클라우드에서 관리하기

1. 코드·작업 규칙·HTML·저장된 일정·자동 생성 시도 기록은 `ckdtjs0911-glitch/Seony_F1`에서 관리합니다.
2. 자동 생성은 GitHub Actions가 실행하므로 사용자의 PC와 Codex 앱이 꺼져 있어도 동작합니다. GitHub 예약 실행은 지연될 수 있으며, 저장된 일정이 없는 세션은 자동으로 탐색하지 않습니다.
3. 새 보고서가 저장되면 실행 요약에 누적 보고서와 HTML 폴더 링크가 나타납니다. 변경이 없을 때는 보고서 링크 전달 작업도 건너뜁니다.
4. Claude는 저장소의 `CLAUDE_CODE_OAUTH_TOKEN` 인증을 사용합니다. 로컬 로그인과 별개이며 설정 여부·실행 성공을 확인하기 전에는 클라우드 첨삭 완료라고 표시하지 않습니다. FastF1 상세 데이터 인증 대기도 별도로 구분합니다.
5. 클라우드 채팅은 `reports/CLOUD_HANDOVER.md`로 이어갑니다. GitHub 실행 결과가 이 로컬 채팅에 자동으로 첨부되는 기능은 구성하지 않았습니다. 중복 수집을 막기 위해 기존 로컬 생성 예약은 클라우드 전환 후 일시 중지합니다.

공개 HTML 링크는 main의 최신 버전을 표시하는 외부 미리보기 서비스입니다. 링크 제공만으로 화면 렌더링을 검증한 것은 아닙니다.

GitHub → Actions → **F1 weekend reports** → **Run workflow**로 수동 실행할 수 있습니다.
특정 주말을 수집하려면 `meeting`에 OpenF1 meeting_key를 입력합니다. 멕시코 2026은 `1298`입니다.

출력: `reports/weekend-<meeting_key>/weekend-report.html`과 `data/<session_key>.json`.
수집에 성공하면 봇이 결과를 저장소에 커밋합니다. 실행 결과 파일은 Actions artifact로도
30일간 보관합니다. 웹사이트 배포나 외부 게시는 하지 않습니다.

처음 사용할 때는 저장소의 Actions가 활성화되어 있어야 합니다. 저장소 정책에서 Actions의
콘텐츠 쓰기 권한을 제한하면 자동 커밋은 실패하지만 artifact는 내려받을 수 있습니다.
포크한 저장소에서는 예약 워크플로를 따로 활성화해야 할 수 있습니다.

## 프랙티스 서킷 재생

새 FP1·FP2·FP3 자료를 수집할 때 해당 세션의 위치 자료도 함께 확보합니다.
왼쪽 표에는 재생 시각까지 완료한 유효 최고 랩과 1위와의 기록 차이, 그 랩의 타이어를 표시합니다.
오른쪽 지도에는 저장된 위치만 표시합니다. 스프린트 주말의 프랙티스 대상은 FP1입니다.

## 인증과 실패 처리

전체 연도 세션 조회가 HTTP 401로 제한되면 저장된 `catalog/sessions.json` 일정으로
종료 세션을 판단합니다. 개별 경기 메타데이터도 같은 제한이면 저장된 일정을 사용합니다.
OpenF1을 먼저 조회하고 성공하면 FastF1을 보조 자료로 수집합니다. OpenF1이 HTTP 401을 반환하면
같은 실행에서 FastF1에 동년·동일 대회·동일 세션 자료가 있는지 확인합니다. 상세 랩이나 공개 결과를
확보하면 사용한 자료의 범위를 명시한 임시 보고서를 게시합니다. 확보한 자료가 없으면 기존 보고서를
보존하고 시도 기록만 남깁니다. 임시 게시 세션도 OpenF1 수집 완료로 기록하지 않습니다.
OpenF1 인증 정보 두 항목이 등록되면 예약 실행이 인증 대기 세션을 한 번 자동으로 다시 조회합니다.
수집이 성공하면 OpenF1 자료를 반영해 재생성합니다. 자동 복구가 실패하면 이후 재시도는 수동 실행으로 합니다.

과거 데이터는 보통 인증 없이 조회할 수 있지만, 라이브 세션이 진행되는 동안에는 과거 데이터에도
인증을 요구할 수 있습니다. 이 경우 실패를 기록하고 마지막으로 성공한 스냅샷을 유지합니다. 429와 일시적인 서버 오류는 같은 실행 안에서만 재시도합니다.

OpenF1 구독 인증을 사용하려면 저장소 Actions secrets에 `OPENF1_CLIENT_ID`와
`OPENF1_CLIENT_SECRET`을 설정합니다. 이 값은 파일이나 커밋에 넣지 않습니다.
일부 세션만 실패하면 정상 세션은 수집하되 실행 자체는 실패로 표시하고, 해당 실행의
artifact에 부분 결과를 남깁니다. 부분 결과는 저장소에 자동 커밋하지 않습니다.

## 로컬 실행

macOS / Linux:

```bash
python -m venv .venv
.venv/bin/pip install requests==2.32.4
.venv/bin/python tools/weekend_report.py
.venv/bin/python tools/weekend_report.py --meeting 1298
.venv/bin/python tools/weekend_report.py --offline reports/weekend-1298
.venv/bin/python -m unittest discover -s tools -p 'test_weekend_report.py'
```

Windows (PowerShell)에서는 `.venv/bin/` 대신 `.venv\Scripts\`를 사용합니다.

```powershell
python -m venv .venv
.venv\Scripts\pip install requests==2.32.4
.venv\Scripts\python tools\weekend_report.py --offline reports\weekend-1298
.venv\Scripts\python -m unittest discover -s tools -p "test_weekend_report.py"
```

`--offline`은 네트워크 없이 `data/` 폴더의 스냅샷만으로 보고서를 다시 만듭니다.

## 보고서 UI

- 레이스 스냅샷에 `data.overtakes`가 있으면 보고서 맨 아래에 전체 API 순위 교환 횟수,
  전 선수의 앞선·뒤처진 횟수, 상대별 시각 내역과 재역전 표시를 제공합니다.
  OpenF1 정의상 피트스톱·경기 후 페널티에 따른 순위 교환도 포함하므로 실제 트랙 추월
  총횟수로 간주하지 않습니다. 같은 두 선수의 직전 교환 방향이 뒤집힌 경우에만
  API 기준 재추월·재추월당함으로 표시하며, 동시 양방향 기록은 순서 미확인입니다.
  원본 미수집은 0건과 구분합니다. 현재 기본 수집 엔드포인트에 overtakes는 포함하지
  않으며, 이번 라스베이거스 수동 보고서에 추가 수집했습니다.

- 각 그랑프리의 수집된 세션 결과표 위에 **입문자를 위한 기록 설명**을 표시합니다.
  프랙티스는 관측 최속, 예선은 API 최종 순위와 Q1·Q2·Q3별 최속,
  레이스는 API 1위와 제공된 완료 랩을 실제 스냅샷에서 가져옵니다.
  랩·섹터·중앙값·타이어·격차·DNF 등의 뜻과 비교 조건의 한계를 함께 설명합니다.
  그리드 페널티나 경기 결과의 원인을 추정하지 않으며, 미제공 기록은 만들지 않습니다.
  주말·최근 3년 누적 HTML에 같은 설명을 적용합니다.

- 세션별 결과표는 10명씩 나눠 보여 주며, 이전/다음 버튼과 구간 버튼으로 이동합니다.
- 검색은 전체 선수를 대상으로 하며, 인쇄할 때는 모든 선수를 표시합니다.
- 랩타임·섹터 차트는 FP1/FP2/FP3/퀄리파잉/레이스 탭과 드라이버 선택으로 탐색합니다.
- 점에 마우스를 올리거나 터치하거나 키보드로 포커스를 주면 0.001초 단위 시간이 표시됩니다.
- 섹터 1·2·3은 차트를 따로 제공하며, 누락된 값은 0초로 대체하지 않습니다.
- 차트 스타일과 스크립트는 `tools/report_charts.css`, `tools/report_charts.js`에 있으며, 보고서를 만들 때 HTML 안에 포함됩니다.

## 해석 기준

퀄리파잉 단계별 기록은 API의 duration 배열을 기준으로 하며, 단계 자료가 없으면 추정하지
않습니다. 롱런 참고 중앙값은 연료·SC·트래픽을 보정하지 않으며 표본 수를 함께 표시합니다.
공식 판정이나 FIA 문서와 별도로 대조하지 않습니다.

멕시코 예시(`weekend-1298`)의 전체 주말 자료도 누적 아카이브에서 선택할 수 있습니다.
완료·미수집 상태는 `reports/index.html`의 해당 세션 정보를 기준으로 확인합니다.

## 보고서 자동 생성

보고서 수집·계산·HTML 생성은 Python 코드로 실행합니다. 데이터 수집 후 누적
보고서를 함께 갱신하고 먼저 저장합니다. Claude 인증이 있으면 아래 검토·rescue 단계를
추가 실행해 검증된 수정사항을 자동 반영합니다. 과거 editorial-review.json은 이전 실행 기록입니다.

### Claude 일반 검토 + rescue 자동 수정

주말 자동 생성과 과거 자료 수집 워크플로 모두 보고서 저장 성공 후 별도 작업으로
`.github/workflows/claude-report-review.yml`을 호출합니다. Claude CLI가 일반 검토 후
rescue를 순서대로 실행합니다. `/cc:review`, `/cc:rescue` 플러그인 명령 자체를 호출하는
방식은 아니며, 같은 목적의 일반 검토와 문제 조사·수정 패치 작성을 별도 요청으로 보냅니다.
`/cc:adversarial-review`는 실행하지 않습니다.

- 일반 검토: 데이터·수치·설명, 구조·UI 회귀, 한국어 문구.
- rescue: 일반 검토 결과를 전달받아 지적을 검증하고 최소 수정 패치를 만듭니다.
  문제가 없으면 수정하지 않습니다. 일반 검토가 실패해도 원본을 직접 확인합니다.
- Claude에는 파일 읽기·검색 도구만 제공하고 MCP 도구와 사용자 훅을 차단합니다.
  실제 수정·테스트·재생성·커밋은 아래 검증 프로그램이 수행합니다.
- `tools/report_rescue.py`는 별도 복사본에서 수정안을 적용하고 전체 단위 테스트를 실행합니다.
  차트 JS를 고쳤으면 문법 검사도 수행합니다. 저장된 원본 스냅샷으로 세션별 보고서와
  누적 보고서를 다시 생성합니다. 외부 OpenF1 자료를 새로 요청하지 않습니다.
- 자동 수정 대상은 보고서 생성·표시 코드 8개(`weekend_report.py`, `build_archive.py`,
  `report_charts.js/css`, `race_events.py`, `race_attachments.py`, `race_pitstops.py`,
  `race_starting_tyres.py`)와 이 코드로 재생성한 HTML·파생 목록 archive-index.json입니다.
  JSON 원본·워크플로·테스트·기타 파일이 바뀌면 거부합니다.
- 모든 검증에 성공한 수정만 별도 게시 작업이 `main`에 일반 커밋·푸시합니다.
  검토한 원본 커밋과 현재 원격 커밋이 다르면 자동 적용을 건너뜁니다. 강제 푸시는 하지 않습니다.
- 결과는 Actions artifact의 `claude-review-f1-weekend-reports` 또는
  `claude-review-historical-f1-reports`에 30일간 저장합니다.
  `review.md`, `rescue.md`, 실행 상태 `status.json`을 확인할 수 있습니다.
  수정 시 제안 패치·검증 로그·검증된 패치와 체크섬도 포함합니다. 실제 게시 결과는
  `claude-rescue-publish-<원본 artifact 이름>`의 `publish-status.json`에서 확인합니다.
- 인증이 없으면 `skipped`, CLI·인증·요청 실패 시 `failed`, 수정안 검증 실패 시
  `repair.status: rejected`로 기록합니다. 이 경우 이미 생성·저장한 원본 보고서를 유지합니다.
  실행 중 상태도 저장하며, 강제 종료된 실행의 기록은 `running`으로 남을 수 있습니다.
  수집·수정 게시 작업끼리만 동시 실행을 막으므로, 검토가 오래 걸려도 다음 수집을 대기시키지 않습니다.

GitHub Actions는 로컬 Claude 로그인 상태를 공유하지 않습니다. Claude Code에서
`claude setup-token`으로 자동화용 토큰을 만든 뒤, **이 저장소**의 Settings → Secrets and
variables → Actions에 `CLAUDE_CODE_OAUTH_TOKEN` 이름으로 등록해야 두 단계가 실행됩니다.
토큰은 채팅이나 파일에 붙여 넣지 않습니다. 만료·취소 시 새 토큰으로 교체합니다.
별도 Anthropic API 키는 사용하지 않으며, Claude 계정의 이용 한도와 사용 정책이 적용됩니다.

로컬 로그인으로 직접 검토하려면 Claude CLI가 PATH에 있는 환경에서 실행합니다.
Git 기준으로 수정·추가·삭제된 `reports/` 파일이 없으면 두 단계를 건너뜁니다.

```bash
python tools/claude_report_review.py --local-login --output-dir /tmp/f1-claude-review
```

로컬 기본 실행은 수정안을 제안만 합니다. `--apply`를 추가하면 복사본에서 자동 반영용
패치를 검증해 저장하지만 로컬 원본을 덮어쓰거나 푸시하지 않습니다. 실제 자동 커밋은
GitHub Actions의 별도 게시 작업에서 수행합니다.


## 사용 타이어와 선수별 한줄 평

랩타임 및 섹터 차트의 점은 사용 타이어 색상으로 표시합니다: H 하드(흰색),
M 미디엄(노란색), S 소프트(빨간색), I 인터미디어트(초록색), W 웨트(파란색).
툴팁에는 정확한 시간과 타이어 코드·이름을 함께 표시합니다. 삭제 랩은 빨간 테두리입니다.
타이어는 stints의 명시된 lap_start/lap_end 범위에 연결합니다. 서로 다른 타이어 범위가
겹치거나 경계·정보가 불명확하면 미확인으로 표시하며, 섹터별로 타이어를 따로 추정하지 않습니다.

선수별 한줄 평은 각 세션의 전체 선수에게 관측 최속·기록 수·API 결과 등의 사실로
생성합니다. 주관적인 실력 평가나 원인 추정은 하지 않습니다. 별도 표에서 10명씩
페이지를 넘기며 전체 검색·인쇄에도 포함됩니다. API 키 없이 생성됩니다.

## 한글 검색

전체 표 검색에서 팀·선수의 주요 한글 표기를 영문 이름으로 연결합니다.
예: `멕라렌`/`맥라렌` → McLaren, `노리스` → Norris,
`키미 안토렐리`/`안토넬리` → Kimi Antonelli, `아이작하자` → Isack Hadjar.
현재 보고서 선수 전체의 성씨와 주요 이름 변형을 지원하며 영문·띄어쓰기 없는 검색도 유지합니다.
이는 등록된 별칭 검색으로, 임의의 모든 오타를 자동 교정하는 기능은 아닙니다.

랩타임·섹터 분석의 검색창도 같은 한글·영문 별칭을 지원합니다. 현재 세션의 선수 목록만
필터링하고 세션을 바꿔도 검색어를 유지하며, 상단 전체 표 검색과는 독립적으로 동작합니다.

모든 등록 팀명의 한글 앞부분 한두 글자도 검색할 수 있습니다. 예: 멕/맥, 페, 메, 레, 애, 알, 윌, 하, 아, 캐.
짧은 검색어가 팀명과 일치하면 팀을 우선 검색하며, 여러 팀명이 겹치면 모두 표시합니다.

## 레이스 주요 상황 · 리타이어

레이스에 한해 race_control 메시지로 SC/VSC, 옐로/더블 옐로, 레드 플래그,
중단·재개·재출발 예정·순서 안내를 시각 및 랩과 함께 표시합니다. 관측 레이스 랩의
시간 범위 밖 메시지는 제외합니다. SC 철수 예고를 실제 재출발로 해석하지 않습니다.
트랙 구간 번호는 랩타임의 세 섹터 번호와 다를 수 있습니다.
DNF·DNS·DSQ는 session_result 기준이며 완료 랩과 마지막 관측 랩을 구분합니다.
확인되지 않은 리타이어 시각·원인은 추정하지 않습니다. 메시지 누락 가능성이 있으므로
타임라인에 없다는 이유만으로 해당 사건이 발생하지 않았다고 판단하지 않습니다.

## 최근 3개 연도 누적 아카이브

`reports/index.html`에서 **년도 → 그랑프리 → 세션**을 선택합니다. 카탈로그와 다운로드 완료는
구분하며 미수집·예정 세션에는 실제 보고서가 없음을 표시합니다. 단일 HTML에 수집된
보고서를 gzip으로 포함하므로 최신 Chrome/Edge에서 인터넷 없이도 선택할 수 있습니다.
선택한 세션을 개별 HTML로 다운로드하는 버튼도 제공합니다.
정기 보고서 생성이 성공하면 아카이브도 갱신되고, 이전 세션 JSON은 삭제하지 않습니다.

전체 원본 수집(올해와 이전 2개 연도):

```bash
.venv/bin/python tools/backfill_openf1.py
.venv/bin/python tools/build_archive.py
```

기본 원본 저장 위치는 저장소의 상위 폴더 `openf1-data/`입니다. `--raw-root`로 바꿀 수 있습니다.
`manifest.sqlite`에 수집 상태·레코드 수·압축 크기·SHA-256을 저장합니다. 재실행 시 검증한
완료 파일을 재사용하고 중단 지점부터 이어갑니다. `--session`으로 특정 세션도 지정할 수 있습니다.
API가 401/403/429를 반환하면 멈추며 접근 제한을 우회하지 않습니다. 404는 미제공으로 기록합니다.
차량·위치 데이터는 선수별로 요청해 gzip JSON으로 보관합니다. 영상·라디오 파일 자체가 아닌,
OpenF1에서 반환하는 JSON 및 라디오 URL 메타데이터를 수집합니다.

원본 대용량 파일은 GitHub에 커밋하지 않습니다. 원본을 장기 보관하려면 해당 폴더를 별도 디스크나
오브젝트 저장소에 백업해야 합니다. 이 환경의 실행·저장 수명을 영구 보관으로 가정하지 않습니다.
전체 수집은 정기 보고서 워크플로와 별도의 장시간 작업이며, 세션 완료 시 로컬 누적 HTML을 갱신합니다.
GitHub Actions 정기 실행은 새 주말의 보고서용 데이터를 수집하고 저장소에 이미 있는 자료를 누적합니다.

## 연도별 보관·삭제

한국 시간 기준 올해를 포함해 최근 3개 연도를 유지합니다.
2026년: 2024·2025·2026 / 2027년: 2025·2026·2027.
과거 2개 연도는 전체 종료 세션을 수집 대상으로 하고, 올해는 종료된 세션을 순차적으로 수집합니다.
원본 수집기와 누적 보고서 생성기 실행 시 기준을 다시 계산합니다. 연도 전환 뒤 첫 실행에서
만료된 세션 JSON·해당 보고서 폴더·카탈로그 항목을 삭제하며, 원본 수집기는 원본 압축 파일과
SQLite 수집 기록도 정리합니다. 원본 폴더별 session.json으로 연도를 기록합니다.

정기 GitHub Actions는 삭제 사항까지 main에 반영합니다. 다만 Git 과거 커밋과 기존에 내려받은
복사본, 만료 전 생성한 Actions artifact는 이 정리로 삭제되지 않습니다. Artifact는 기존 30일
보관 정책에 따라 만료됩니다. 이 기능은 현재 자료 보관 정책이며 Git 이력을 재작성하지 않습니다.
현재 수집이 끝나지 않은 연도는 "전체 수집 대상"이지 "이미 전부 수집 완료"를 뜻하지 않습니다.

과거 원본 수집은 2단계로 진행합니다. 먼저 전체 대상 세션의 보고서용 6개 데이터셋을 수집하고,
그다음 날씨·추가 원본과 선수별 대용량 텔레메트리를 수집합니다. 누적 보고서 목록은 수집 중 주기적으로 갱신하고, 전체 조회 종료 시 다시 갱신합니다.

미수집 보고서 전체를 우선 채우려면 `.venv/bin/python tools/backfill_reports.py`를 실행합니다.
대회별 일괄 조회 결과를 세션별로 분리하고 검증용 원본과 보고서 스냅샷을 함께 저장합니다.
그 뒤 `.venv/bin/python tools/backfill_openf1.py --telemetry-only`로 나머지 원본을 이어받을 수 있습니다.

GitHub의 `Fill historical report gaps` 워크플로는 매주 월요일 한국 시간 03:43에 과거 누락 보고서를
확인하며 Actions에서 수동 실행할 수도 있습니다. API 카탈로그를 갱신하고 현재 연도의 자료는
다시 조회합니다. 텔레메트리 전체 원본은 이 보고서 보충 워크플로와 별도의 저장·수집 대상입니다.

## 레이스 컴파운드 참고자료와 스타트 타이어

레이스 섹션의 **그랑프리별 타이어 컴파운드와 스타트 타이어**에서 컴파운드는 해당 연도의
사용자 제공 참고자료에 있는 선택 대회 카드로 표시합니다. 원본 PNG는 `reports/attachments/`에
그대로 보존하며 별도 검증된 공식 데이터로 취급하지 않습니다.

스타트 타이어는 고정 PNG 대신 저장된 OpenF1 레이스 스냅샷으로 매번 집계합니다.
해당 연도 모든 그랑프리의 S/M/H/I/W·미확인 인원, 출발 인원, DNS·출발 여부 미확인을 표시합니다.
선택한 대회는 선수별 타이어와 팀도 함께 확인할 수 있습니다. 다른 연도의 원본은 합산하지 않습니다.
DNS는 스틴트나 L1 기록이 있어도 출발 인원에서 제외합니다. 첫 랩 DNF는 출발로 포함하고,
출발 근거가 없는 스틴트만으로 참가를 추정하지 않습니다.
최초 L1을 포함하는 명시된 스틴트에서 컴파운드를 확인하며, L1 자료가 없거나 상충하면 미확인입니다.
재출발과 후속 타이어 교체는 최초 스타트 집계에 넣지 않습니다.

새 레이스가 수집되면 이전 대회의 화면에 표시되는 같은 연도 집계도 갱신합니다.
주말 보고서·누적 보고서에 동일한 자료가 들어가며 인터넷 없이도 볼 수 있습니다.
수집하지 않은 레이스는 수집 대기, 예정된 레이스는 레이스 전으로 표시합니다.
참고자료 manifest가 없는 다음 연도에도 저장된 레이스가 있으면 스타트 타이어 집계는 표시합니다.
최근 3년 보관 정책이 만료된 이미지와 manifest 항목은 기존 정책에 따라 정리합니다.

레이스 보고서 맨 아래에는 팀·선수별 피트스탑 기록을, 그 바로 아래 마지막 항목으로 타이어
참고 이미지를 표시합니다. 기록 랩·한국 시간·lane_duration(레인 통과)을
표시하며 기존 pit_duration만 있으면 필드명을 명시합니다. 누락 시간을 추정하지 않습니다.
관측 레이스 시간 범위 밖 이벤트는 제외하고, 날짜 없는 이벤트는 범위 미확인으로 표시합니다.
피트 기록 영역도 전체 표 검색의 한글 팀·선수 별칭을 지원합니다.

피트 date는 API 이벤트 기록 시각으로 표시하며 정확한 진입·출구 시각을 추정하지 않습니다.
레인 통과 시간에는 대기·경기 중단 영향이 포함될 수 있어 타이어 교체 작업 시간으로 해석하지 않습니다.

피트스탑 기록 바로 위에 전용 선수·팀 검색창과 선수 선택 메뉴가 있습니다. 기존과 같은
한글·영문 별칭 및 짧은 팀명 검색을 지원하며, 선택 메뉴에는 순위·번호·선수명·팀명을 표시합니다.
전체 선수로 되돌리거나 팀 검색 후 특정 선수를 골라 볼 수 있습니다.

타이어 컴파운드 항목은 시즌 전체 이미지를 반복 표시하지 않고 선택한 대회의 H/M/S와
C 번호만 카드로 표시합니다. 사용자 제공 이미지의 2026년 20개 대회 행을 circuit_key로
연결했으며 자료에 없는 대회는 추정하지 않고 미제공으로 표시합니다. 스타트 타이어 자료는 별도 항목입니다.

피트 표 열은 기록 번호 / 랩 / 기록 시각(한국 시간) / 피트 레인 통과 시간 / 컴파운드입니다.
정차 시간 열은 표시하지 않습니다. 컴파운드는 해당 선수의 피트 랩 또는 다음 랩에서 시작하며
직전 스틴트와 랩 범위가 연속된 다음 스틴트에서 연결합니다. 후보가 여러 개이거나 경계가
누락·중첩된 경우 미확인으로 남깁니다. API 스틴트 연결이며 실제 교체·새 세트 여부를 단정하지 않습니다.

## 레이스 데이터 영상

FastF1은 고정된 `vendor/Fast-F1` 소스를 설치한 뒤 `tools/fastf1_source.py`로 실제 조회합니다.
해당 연도·장소의 유일한 이벤트와 세션 이름·시작 시각(6시간 이내)을 확인합니다. 공개 일정과
Ergast/Jolpica 결과는 별도로 수집합니다. 상세 타이밍 서버가 401이면 로그인 입력을 시도하지
않고 결과 조회 성공·상세 인증 대기를 분리해 표시합니다. 운영자 인증 설정 후 명시적인
`--authenticated` 실행으로 랩·차량 자료를 수집할 수 있습니다. 동일 번호·약어·랩을 맞춰
0.002초 초과 차이를 집계하고 기존 OpenF1 원본을 덮어쓰지 않습니다. 같은 타이밍 원본을
공유할 수 있으므로 독립 검증을 뜻하지 않습니다. 캐시·비밀값은 Git에 넣지 않습니다.

지도는 가로가 길도록 같은 회전을 본선·차량·피트 참고선에 적용합니다. 피트 참고선은
`reports/geometry/`의 OpenStreetMap way를 해당 서킷 외곽선과 세션 좌표에 근사 정합한
청록색 실선입니다. 실제 관측 차량 궤적과 구분하고 ODbL 출처를 표시합니다. 확인되지 않은
서킷은 지도 피트 경로를 만들지 않습니다. 상황 카드가 폭을 넘으면 다음 줄로 내려갑니다.

지도 재생은 기본 4배속입니다. 레이스 상황 타임라인은 원문 대신 한국어 카드·범위·시각과
시간 순서 화살표를 표시합니다. 퀄리파잉은 `qualifying_replay.py`로 실제 location을 수집해
별도 압축 파일에 보관합니다. Q1/Q2/Q3 구간 선택, 단계별 참여 선수 위치, 그 시점까지 완료한
유효 최고 랩과 1위 기록 차이를 표시합니다. 삭제 확인 랩·아웃랩은 기록표에서 제외하며
미완료 랩이나 미래 기록을 미리 표시하지 않습니다. Q 단계 자료가 없으면 구간을 만들지 않습니다.
MP4·두 선수 차량 비교를 퀄리파잉에 복사하지 않습니다. 자동 수집 단계에서도 일반 퀄리파잉을
처리하며 중지 기간과 종료 3시간 정책은 그대로 유지합니다.

순위 흐름 MP4에는 영상 기준 0.25·0.5·0.75·1·1.25·1.5·1.75·2배속 메뉴를 별도로 둡니다.
오른쪽 이름표에는 배경 상자를 그리지 않습니다. 지도·선수 비교 메뉴는 1·4·8·16·32배속입니다.

속도 메뉴는 1·4·8·16·32배속으로 통일합니다. 지도와 원형 간격을 나란히 보여주며,
순위 MP4 이름표는 오른쪽 끝에서 세로로 움직입니다. `enrich_pits`는 API pit의 lap_number와
해당 선수의 완성 랩을 연결해 PIT LAP 구간을 표시합니다. 정확한 입출구 상태를 뜻하지 않습니다.
해당 구간 location에서 본선과 떨어진 연속 관측이 확인될 때만 점선 추정 피트 경로를 만듭니다.
관측 분리가 없으면 분리 경로 미확인으로 표시합니다. 피트·랩·트랙 내용 해시가 같으면 재계산하지 않습니다.

화면은 가로형 시간별 서킷 위치·시간 간격 → 순위 흐름 MP4 → 두 선수 선택 비교 순서입니다.
고정 결승 1·2위 비교 MP4는 새로 만들거나 표시하지 않습니다. `race_gaps.py`가 원본 intervals와
전체 선수 location을 수집하며, 좌표는 최소 0.5초 간격으로 압축 보관합니다. 실제 좌표 지도와
선두 시간차를 펼친 가로 보기를 나란히 배치합니다. 이름 옆 수치는 앞차 기준 interval이며
s(초)를 사용합니다. 최근 10초 내 interval이 없으면 —, 위치가 2초 넘게 비면 숨깁니다.
랩 차이는 원문 +1 LAP 등을 보존합니다. `gap_to_leader`를 앞차와의 간격으로 쓰지 않습니다.
순위 흐름 MP4에도 같은 시각의 interval을 표시합니다. 참고 사이트 11326은 첨부 UI 화면만
참고했으며 대상 레이스의 수치 검증 자료로 사용하지 않습니다.

Race에만 영상·두 선수 비교 재생을 표시합니다. `tools/compare_player.py`는 레이스 전체
참가자의 차량 데이터를 수집해 `*-compare.json.gz`에 저장합니다. 세션·랩·선수 자료의
내용 해시가 같고 수집이 완료됐다면 재조회하지 않습니다. 누락 선수는 선택 목록과 화면에서
구분하고, 인증·데이터 부족을 임의의 수치로 채우지 않습니다. 일부 수집 실패는 자동으로 다시
조회하지 않고 수동 실행에서 재시도합니다. 브라우저에서 두 선수·공통 랩·속도를 선택할 수 있으며 같은 UTC 시각에서
최근 1초 이내 관측만 표시합니다. 실제 주행 시각이 겹치지 않는 랩은 선택 목록에서 뺍니다.

MP4는 음소거 자동 재생·반복이고 차량 비교 화면도 선택 후 자동 재생합니다. DRS 값이
없는 경우 항목 자체를 생략합니다. 순위 흐름 MP4는 점과 이름표를 함께 부드럽게 움직이되
측정 기록 사이의 이동은 표시용임을 명시합니다. 고정 비교 MP4는 표시하지 않습니다.

실질적인 새 데이터 수집에 성공한 실행에서 `tools/report_video.py`가 최근 수집된 레이스의
결승 1·2위 공통 주행 구간 car_data와 전체 position 기록을 가져옵니다. 기존 스냅샷을 덮어쓰지
않고 `weekend-*/media/*-video-data.json`에 응답·수집 시각·출처·동기화 구간을 보관합니다.
차량 데이터 수집 실패 시 해당 영상 생성은 실패로 기록하고 기존 영상을 보존하며 보고서 수집
성공과 구분합니다. OpenF1 인증 설정은 기존 클라이언트를 그대로 사용합니다.

같은 UTC 시각에서 과거 샘플을 유지하며 1초 초과 공백은 미제공으로 표시합니다.
속도·가속·브레이크 사용 그래프, 기어·DRS 상태는 두 선수 선택 재생으로 제공합니다.
우승자 각 랩 완료 시점의 전체 순위 흐름 30초 MP4를 만듭니다. 브레이크 압력·실제 추월 횟수는 추정하지 않습니다.
position은 변화 이벤트이므로 다음 순위 갱신까지 유지하며 은퇴 선수의 이전 순위가 남을 수 있습니다.
순위 차트는 최종 공식 결과를 대체하지 않습니다.

HTML에 MP4를 내장하므로 별도 파일 없이 오프라인 재생과 다운로드가 가능합니다.
주말·레이스·누적 보고서에 동일한 영상이 들어갑니다. 원본 내용과 생성기 버전이 같으면
영상과 보고서를 다시 만들지 않습니다. 실제 화면 변경 시 `VERSION`을 올려 갱신합니다.
Linux 실행은 `fonts-nanum`과 `tools/video-requirements.txt`의 의존성을 설치합니다.
